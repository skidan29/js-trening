# Design

## Context

См. `proposal.md` — мотивация. Приложение уже использует Vite + React (JS), React Router, реестр инструментов в `src/tools.js`, общий `BackLink` и единый `src/styles.css`. Часы (`src/pages/ClockPage.jsx`) показывают текущее время через `setInterval` и `Date`, но измеряют не прошедшее время, а стенное, поэтому их логика для секундомера не подходит.

## Goals / Non-Goals

**Goals:**
- Добавить секундомер без изменения поведения часов и калькулятора.
- Точный отсчёт, устойчивый к throttling вкладки.
- Минимальный код в стиле существующих страниц.

**Non-Goals:**
- Круги (lap), сохранение результатов, несколько таймеров.
- Сохранение состояния в localStorage или между переходами.
- Общий хук таймера для часов и секундомера.

## Decisions

### Регистрация инструмента и маршрут
В `src/tools.js` добавляется `{ id: 'stopwatch', title: 'Секундомер', path: '/stopwatch' }`, в `src/App.jsx` — `<Route path="/stopwatch" element={<StopwatchPage />} />`. Стартовая страница уже рендерит карточки из реестра, поэтому её код не меняется. Альтернатива — хардкод карточки — отброшена: реестр для этого и создан.

### Модель времени
Храним:
- `accumulatedMs` — накопленное время до последнего запуска;
- `startedAt` — `Date.now()` момента запуска (или `null`, если стоим).

`elapsed = accumulatedMs + (startedAt ? Date.now() - startedAt : 0)`.

Альтернатива «прибавлять 50 мс на каждом тике» отброшена: при throttling вкладки и дрейфе таймера она даёт неверное время. Пересчёт от `Date.now()` самокорректируется.

### Состояния и переходы
Три состояния: `idle`, `running`, `paused`. Производное состояние определяется флагами `startedAt !== null` и `accumulatedMs > 0` / явным полем `status`, чтобы различать «покой» и «паузу».

- `start()`: если не запущен — `startedAt = Date.now()`, статус `running`; из паузы `accumulatedMs` уже содержит накопленное, поэтому отсчёт продолжается.
- `stop()`: если запущен — `accumulatedMs += Date.now() - startedAt`, `startedAt = null`, статус `paused`.
- `reset()`: `accumulatedMs = 0`, `startedAt = null`, статус `idle`.

Обработчики защищены проверками, поэтому повторные нажатия не ломают состояние (идемпотентны). Кнопки: «Старт» активна в `idle`/`paused`, «Стоп» — только в `running`, «Сброс» — всегда. Это UX-уточнение, спек не нарушает.

### Обновление отображения
Пока `running`, `setInterval` раз в 50 мс обновляет «тиковое» состояние, вызывая перерисовку; само время каждый раз вычисляется из `Date.now()`. Интервал создаётся в `useEffect` с зависимостью от статуса и очищается при остановке и размонтировании (важно для StrictMode). Частота 50 мс даёт плавность и превышает требуемые 10 обновлений/с.

### Формат
Хелпер `formatStopwatch(ms)`: `minutes = floor(ms / 60000)`, `seconds = floor(ms / 1000) % 60`, `centis = floor(ms / 10) % 100`, каждый компонент через `padStart` (минуты минимум 2 знака, при превышении 99 растут естественно). Возвращает `мм:сс.сс`.

### UI и стили
`src/pages/StopwatchPage.jsx` повторяет каркас других страниц: `BackLink`, заголовок, крупный дисплей и ряд из трёх кнопок. Новые классы в `src/styles.css`: `.stopwatch-display` (стилистика как `.clock-display`), `.stopwatch-controls` (flex/grid на три кнопки), `.stopwatch-button` с модификаторами старта/стопа/сброса. На узком экране кнопки остаются в ряд и не выходят за контейнер.

### Отсутствие сохранения
Состояние живёт только в компоненте. Переход на другую страницу размонтирует его, возврат даёт `00:00.00` и `idle` — как требует спека.

## Risks / Trade-offs

- `setInterval` не тикает в фоновой вкладке → время всё равно корректно, так как считается от `Date.now()`; обновится при возврате фокуса.
- StrictMode дважды монтирует эффект в dev → очистка интервала в cleanup предотвращает двойной отсчёт.
- Точность ограничена сотыми долями → отображение может «перескакивать» на 1–2 сотых при нагрузке; для MVP приемлемо.
- Нет тестов → проверка ручная по сценариям из спеки.

## Migration Plan

Изменение аддитивное: новый файл, одна запись в реестре, один маршрут и стили. Миграции данных нет; откат — удалить страницу, запись, маршрут и новые CSS-правила.
